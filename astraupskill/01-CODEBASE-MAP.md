# 01. Codebase map

Start at `src/domain/inventory.ts`. `InventoryItem` stores `onHand` and `reservedQuantity`; available quantity is derived as `onHand - reservedQuantity`. `InventoryReservation` records the item, quantity, reason, creator, and active or released status. `LowStockAlert` is derived from available quantity and an item reorder point. Keeping the derived value out of storage avoids a second number that could drift.

HTTP entry points live under `src/app/api`. `POST /api/items` creates an item, `PATCH /api/items/:itemId` updates metadata, and `POST /api/items/:itemId/adjust-stock` changes on-hand stock. `POST /api/reservations` creates a hold and `POST /api/reservations/:reservationId/release` releases one. Route wrappers call `withAuth` and `withRole`; Zod schemas in `src/lib/validation` check request shape before service code runs. Existing role behavior remains: owners and managers manage inventory, while clerks can create and release their own holds.

The service layer is the business boundary. `createInventoryService` validates the manager role, creates or updates items, rejects stock below zero or below reservations, and calls `AlertService`. `createReservationService` checks role, reads an item, checks availability, increments `reservedQuantity`, creates a reservation, and synchronizes its alert. Release performs the inverse and rejects an already released reservation. The repair places each multi-step service mutation inside `repository.runExclusive`.

`src/repositories/inventoryRepository.ts` is the replaceable contract. The new `runExclusive<T>` method is the explicit capability required by services. `src/repositories/inMemoryInventoryRepository.ts` implements it with a FIFO promise tail. Before the callback, it clones each Map. If the callback throws, the maps are replaced by those clones; a `finally` release lets the next queued operation proceed. Every read still returns a clone, so callers cannot mutate repository state without a write method.

The tests use the same real in-memory repository class and service factories as the application. `tests/register-alias.mjs` resolves `@/` imports for Node 22's TypeScript strip-types mode. No server, database, or external service is needed. When reading the change, compare the current files to the exact originals in `snapshots/` to see the smallest behavioral boundary that changed.

For a CRUD review, distinguish command endpoints from read endpoints. `GET /api/items` and `GET /api/alerts` can return repository clones without entering the mutation queue. `PATCH` and adjustment routes are commands: they validate the actor, validate the domain transition, persist, and return the post-write record. Reservation creation and release are commands with more than one write, so their boundary includes every repository call until the response object is ready. This map helps prevent a future developer from adding a new write after the lock merely because the current UI does not display that field.

The component is useful as a consumer map, not as a security boundary. `inventory-workbench.tsx` submits forms and renders returned items, reservations, and alerts. A browser can be modified, a stale tab can submit old values, and a script can call the route directly. Consequently the service and repository invariants are the load-bearing part of this improvement. The route remains thin enough that the same service factories can be tested without starting Next.
